# 評価契約の不変条件（リポ固有）

評価結果の信頼性は本ツールの中核（README「評価契約」）。以下はコードが破ってはならない不変条件で、変更・緩和は builder の判断で行わず、main が設計しユーザー承認を経る。詳細と境界値は各 REQ-n を spec で確認する（[spec-reference](./spec-reference.md)）。

## データの分割と凍結（REQ-17）

- 分割は group 単位で行い、seed・分割規則・各分割のハッシュを記録する
- 評価データは凍結し、ハッシュが記録と一致しなければ処理を停止する（fail-closed）
- 評価データが無い場合、`evaluate` は `status:"skipped"`・exit 0 とし、評価済みを装わない

## 評価の独立性（REQ-27）

- 評価の前後でモデル（重み・語彙・校正・しきい値）と評価データのハッシュが一致すること
- 推論関数には `input` だけを渡す（正解ラベル・分割情報・評価データの統計を推論側へ漏らさない）
- 凍結した最終 test への適用は 1 回限り。最終 test の結果を見て候補・しきい値を選び直さない

## 有意性・指標（REQ-24・REQ-25・REQ-26）

- 下限基準（majority）との比較は McNemar 検定（p < 0.05）。複数候補の比較は Holm 補正を行う。件数不足は「判定不能」として返し、合格扱いにしない
- 分母が 0 の指標は `null` とし、平均から除外する（0 や 1 で埋めない）
- 型の正しさと意味の正しさは別々に数える（`type_meaning_quadrant`）
- 再現性は 3 seed 以上の Wilson 95% 信頼区間の重なりで示す

## 推論の一致（REQ-28）

- 1 件ずつの推論とバッチ推論の結果が全件一致すること（PoC-16 でバッチ側の不一致を実際に検出した経緯がある）

## 入出力契約（REQ-21・REQ-33）

- 終了コードは 7 種に固定: `ok`=0・`judged_fail`=10・`out_of_scope`=11・`pending`=12・`limit_exceeded`=20・`invalid_input`=64・`runtime_error`=70
- CLI は 7 工程（`register → inspect → train → evaluate → select → package → infer`）。出力は 1 呼び出しにつき JSON 1 つ（例外は `infer --input-file` の 1 行 1 JSON のみ）
- チェックポイントからの再開は提供しない（REQ-34）

## 決定性と証拠の種別

- 同一マシン・同一 seed・同一依存版で予測ラベルが全件一致すること。浮動小数の許容差は 1e-9
- MLX の GPU 学習は同一 seed でも完全再現しない。決定的な再現が必要なテストは CPU で行い、GPU の非決定性をテストの許容幅拡大で吸収しない
- 測定値・判定を記録する際は証拠の種別（テストハーネス / 模擬 / 推定 / 実機）を必ず明記する

## テスト

- 上記の各不変条件には、違反時に失敗する機械照合テスト（ハッシュ不一致で停止する・分母 0 で `null` になる・終了コードの値など）を置き、テスト名またはドキュメントコメントに REQ-n を記す
