# Claude Code プラグインの公開前チェックリスト

対応: REQ-33・REQ-36・REQ-38・REQ-39・REQ-41・#726・#760。導入手順と実機確認の手順は [plugin-install-procedure](plugin-install-procedure.md)。

## 1. 目的と読み方

- 目的: プラグイン（`plugin/`・`.claude-plugin/`）を人に使ってもらう前に確かめることと、その状態を 1 か所で見られるようにする。
- 担当: 「AI」は Agent が確かめて記録する項目。「人」は実機・判断・外への操作が要る項目で、Agent は準備までに留める。
- 証拠種別は [evaluation-contract](../../.claude/rules/evaluation-contract.md) の区別（テストハーネス / 模擬 / 推定 / 実機）に従う。
- 状態が変わったら本表を直す。版を上げるたびに第 2 節を上から確かめ直す。

## 2. 確かめること

| 項目 | 担当 | 状態 | 証拠 |
| ---- | ---- | ---- | ---- |
| プラグインから判定を呼べる。常駐は使われなければ自分で終わる | 人 | 済 | 実機。2026-11-16。#726 のコメント（#731 の記録） |
| 許可ルールは判定ラッパーだけを許す 1 行で足りる | 人 | 済 | 実機。2026-11-18。#726 のコメント |
| 実際の作業の中で判定を呼んで、手間と一致を見た | 人 | 済 | 実機。2026-11-16。#726・#704 のコメント（#742 の記録） |
| 判定の履歴が競合で欠けない | AI | 済 | テストハーネス。#748・#749 |

## 3. 人の操作として残っていること

| 項目 | 状態 | 補足 |
| ---- | ---- | ---- |
| 版のタグ `v0.1.0` を切って push する | 未 | 手順は [plugin-install-procedure](plugin-install-procedure.md) 第 4 節。タグが無い間、`--tag` を指定した導入コマンドは失敗する。タグの push はオーナーが行う |
| タグの後、GitHub から導入できるかを確かめる | 未 | `cargo install --git … --tag v0.1.0` と `claude plugin marketplace add Fandhe-AI/fandhe-edge-model`。プラグインの置き場所と、更新したときに許可ルールのパスが変わるかも見る（手順書の第 2 節 4・5 の未確認事項） |
| 使ってもらう相手へ、モデル（パッケージ）をどう渡すか決める | 未 | モデル・例文・評価データは配布していない。相手が自分で作るか、手元で作ったパッケージを渡すかで、導入の案内が変わる |
| 使ってもらう相手へ案内する | 未 | 上の 3 つの後 |

## 4. 決めていないこと

- 常駐での 1 件の時間の上限と、アイドル終了の既定値（600 秒）は、実機の計測（#710）の後に見直すと書いたままで、まだ見直していない。
- 利用記録を例文に使って正答率を上げる作業（#756）は、公開の前に行う予定。
- macOS（Apple Silicon）以外での動作は確かめていない。
