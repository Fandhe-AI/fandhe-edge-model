対応: REQ-41・TASK-41.1（本リポの分割では TASK-41.1-9）・PoC-26・M12・issue #394。事前登録は [poc26-preregistration](./poc26-preregistration.md)・[追補 1](./poc26-preregistration-addendum-1.md)。

- 本書は判断材料と確定案。REQ-41 の扱い・受け入れ基準・アーキテクチャの確定はオーナーが行い、判断は #394 と末尾の「判断の記録」に残す
- spec（`02-poc-plan.md` PoC-26・`04-requirements.md` REQ-41・`06-roadmap.md` M12）への反映もオーナーが判断する。本リポから `docs/spec` は編集しない
- 数値は各 issue の結果コメントからの転記。証拠の種別は特記が無ければ実機（Mac）

| 成功基準（PoC-26・暫定） | 結果 | 出典 |
| ---- | ---- | ---- |

| ② 容量・RSS・p95 と 40 MB・2 GB・250 ms の関係 | 示せた。3 項目とも満たさない（容量 1001 MB・p95 1084 ms・RSS 2160.8 MB。GPU・bf16。参考扱い） | #393 |

| ④ REQ-41 の受け入れ基準と初期アーキテクチャの材料 | 本書の「確定案」 | #394 |

結論（案）: 候補 P（Qwen2.5-0.5B-Instruct＋LoRA）は、この課題では既定候補 C3（バイト CNN・配布 0.6 MB）と平均正解率が近く（0.816・0.818）、C3 を有意に上回る証拠は得られなかった（同等性は検定していない）。一方で容量は約 1650 倍・p95 は 250 ms の約 4 倍になる。REQ-41 を M12 の Must として実装へ進める根拠は得られなかった。

追加検証（④・#559）: 新しい凍結 test で、7B（P7）は C3 を 3 seed とも有意に上回った（平均正解率 0.824 対 0.607）。1.5B（P15）も同様（0.773）。一方で重みは 3〜15 GB、今の採点方式では 1 件 2.6〜13 秒かかる。再開条件の第 2 項は満たさず、第 3 項も今のままでは満たさない（P15 は採点方式の改善と軽量化で速度が届く可能性がある。推定）。

## 結果

### ① 品質差（凍結 test n=324・正解率と Wilson 95% 区間）

| 候補 | seed 0 | seed 1 | seed 2 |
| ---- | ---- | ---- | ---- |
| C1 | 0.494 | 0.503 | 0.552 |
| C3 | 0.824 | 0.833 | 0.796 |
| P | 0.836 [0.792, 0.873] | 0.796 [0.749, 0.837] | 0.815 [0.769, 0.853] |

- 有意性（事前登録どおり seed ごとに Holm の m=3）: P 対 majority・P 対 C1 は 3 seed とも有意（P 対 C1 の b/c は 129/18・117/22・110/25）。P 対 C3 は 3 seed とも有意差なし（補正後 p=0.728・0.213・0.594）。seed 1 は C3 の正解数が多い
- 事前登録の「有意に上回る」（3 seed すべてで Holm 後 p<0.05 かつ b>c）は、P 対 C3 で不成立
- 再現性: 各候補の 3 seed の Wilson 区間は互いに重なる（REQ-26）
- P の代表構成は iters 600・lr 5e-5（validation 0.824。他の 3 構成は 0.787）。学習は約 300 秒/seed、MLX ピーク約 4.65 GB
- autoregressive は欠測（7 工程の `train` で学習できず、推論ランタイムが C1・C3 のみ対応のため。オーナー承認 2026-10-08・#389）
- 解釈の限界: データは LLM 生成で人手確認なし。評価の約 1/4 は train と同型の値差し替え（#387）。課題は 1 つ（Playwright MCP のツール選択・26 ラベル）だけで、事前学習の知識が効く課題での差は測っていない

### ② 容量・RSS・p95（#393。2026-10-09。証拠: 実機・参考扱い `reference_only`）

| 条件 | p95（<250 ms） | 平均 | RSS `time -l`（<2 GiB＝2147.5 MB） | MLX ピーク |
| ---- | ---- | ---- | ---- | ---- |
| GPU・bf16 | 1083.9 ms | 967.6 ms | 2160.8 MB | 1962.8 MB |
| CPU・bf16 | 15659.6 ms | 13393.3 ms | 2740.6 MB | 1271.4 MB |

- 容量: 1001.017 MB（目安 40 MB の約 25 倍。ほぼ全量が base の `model.safetensors`）。参考の ONNX（float32・LoRA 統合）は 1976.256 MB
- 他アプリを閉じられず `--quiet-machine` なしで実行（開始時 load average 3.03 / 3.86 / 3.63）。容量は負荷の影響を受けず、p95 は約 4 倍の差で判定は変わらない見込み。RSS（GPU）は 13 MB 超の境界値で、静かな状態なら下回る可能性がある
- 採点は 1 件あたり K=26 選択肢を 8 件ずつ forward（4 回）。RSS はモデル読み込みを含む実行全体のピーク
- 測り直さず参考値のまま進める（オーナー判断 2026-10-09）

### ④ 追加検証: 大きめの Qwen（#559。2026-10-14〜16。証拠: 実機・GPU・bf16）

条件は[追補 2](./poc26-preregistration-addendum-2.md)で結果を見る前に固定した。主候補は P7（Qwen2.5-7B-Instruct）、P15（Qwen2.5-1.5B-Instruct）と P（0.5B）は参考扱い。

- 対象外にしたもの（結果を見る前に追補 2 で固定）: 3B は Qwen Research License のため除外（1 節）。量子化（QLoRA など）は別の候補になるため除外（5 節）。14B 以上は bf16 で約 30 GB になり、32 GB の検証機では 7B でも batch 4 が swap 超過だったため試していない
- 比較条件: C1・C3 は新しいプロジェクトで再学習した新しい個体、P は #389 の adapter をそのまま使った（#555）。P15・P7 は新規に学習した

正式: 新しい凍結 test（`885a5ca0…`、324 件。#554・#555）の正解率

| 候補 | seed 0 | seed 1 | seed 2 | 対 C3（b / c、Holm 後 p） |
| ---- | ---- | ---- | ---- | ---- |
| C1 | 0.364 | 0.336 | 0.401 | — |
| C3 | 0.577 | 0.620 | 0.624 | — |
| P | 0.670 | 0.611 | 0.620 | seed 0 のみ有意に上（78/48・65/68・65/66。p 0.0095・0.862・1。#555） |
| P15 | 0.778 | 0.759 | 0.781 | 3 seed とも有意に上（95/30・80/35・84/33。p 4.7e-09・3.3e-05・2.7e-06。#556） |
| **P7** | **0.833** | **0.821** | **0.818** | **3 seed とも有意に上（106/23・97/32・89/26。p 6.3e-14・8.5e-09・3.0e-09。#557）** |

- 判定（追補 2 の 8 節）: 主候補 P7 は C3 を 3 seed すべてで有意に上回った（Holm 後 p < 0.05 かつ b > c）。対 majority・C1 も 3 seed とも有意
- 結論（追補 2 の 1 節で固定した読み方）: 「同じ課題で、大きい Qwen は C3 を有意に上回る」。再開条件の第 1 項を再検討する材料にする。本課題が「C3 が届かない課題」に当たるかは、この結果からは判断しない
- 参考値: 旧凍結 test（`55b278ed…`）では P7 0.920・0.920・0.914、P15 0.892・0.864・0.864（C3 0.824・0.833・0.796）。同じ評価データの使い回しのため甘めに出る。判断には使わない
- 新しい test では C3 も P も旧 test より大きく下がった（C3 平均 0.818 → 0.607、P 0.816 → 0.634）。旧 test と train の型の近さ（①の解釈の限界）が効いていたと考えられる（推定）
- 新しい test の注記（#554）: Claude で生成し、fable が全件を審査した。近接重複が 15 行（約 4.6%。基準 16 行以下）残る。3 巡で 130 group → 116 group を作り直した。審査者は 1 人で、巡によって判定がぶれた
- P7 は 32 GB に batch 4 では載らず（swap 増 564.6 MiB > 512 MiB）、batch 2 で学習した（追補 2 の 5 節）。学習に使った例は 300 iters × 2 = 600 件で train 864 件の 1 周に満たない（P・P15 は 1200 件）。P7 の正解率はこの不利を含んだ値
- 代表構成: P15・P7 とも iters 300・lr 1e-4（validation の正解率 P15 0.889・P7 0.907）。決定性は P15 だけ確認し、validation 108/108 件一致

| 項目 | P（0.5B） | P15（1.5B） | P7（7B） |
| ---- | ---- | ---- | ---- |
| ベース重み | 1001 MB | 3087 MB | 15,231 MB（4 シャード） |
| adapter | — | 10.6 MB | 23.1 MB |
| 学習のメモリ（ピーク） | 約 4.65 GB | 約 7.37 GB | 約 18.3 GB |
| 学習時間（1 seed） | 約 300 秒 | 約 229 秒 | 458〜529 秒 |
| `predict` の 1 件あたり（新 test。平均・p95） | 参考: 0.97 秒・1.08 秒（②） | 2.56 秒・2.83 秒 | 13.3〜13.4 秒・14.9〜15.3 秒 |
| `predict` のメモリ（MLX ピーク。`predict` の `run.json`） | — | 約 4.15 GB | 約 16.6 GB |

- 容量・RSS・p95 の本測定（`measure.py`）と ONNX 書き出しは、追補 2 の 9 節により行っていない。GB は 10^9 B
- `predict` の時間は 1 件ごとに 26 選択肢の「プロンプト＋選択肢」の列を 8 本ずつ 4 回 forward した合計。プロンプトは平均 223 トークン（うち system 部分 176）、選択肢は平均 3.7 トークンで、1 件あたり約 5,900 トークンを計算している。参考: C1・C3 の推論は 1 件 0.09〜11.4 ms（PoC-14）
- 共通プロンプトを 1 回だけ計算する採点（確定案 3 の 4、KV の使い回し）にすると約 320 トークンになり、計算量は約 1/18。時間が計算量に比例するなら P7 は 1 件 0.7 秒前後、P15 は 0.14 秒前後（推定・未測定。1 回の forward の固定費があるため、実際はこれより遅い）
- 再開条件の第 2 項（容量 100 MB 級以下）は、P15・P7 とも満たさない（重み 3〜15 GB）。第 3 項（p95 250 ms 未満・RSS 2 GiB 未満）は、P15 の速度は KV の使い回しで届く可能性がある（推定）が、bf16 の重み 3 GB だけで RSS 2 GiB を超える

## 確定案

### 1. REQ-41 の扱い

| 案 | 内容 | 長所 | 短所 |
| ---- | ---- | ---- | ---- |
| **A（推奨）** | REQ-41 を M12 の Must から外し「検討中」へ戻す。PoC-26 の結果と再開条件を spec に残す | C3 を有意に上回る証拠が無い候補のために、汎用 ONNX 演算・外部データ・BPE トークナイザー・GB 級の資源上限を抱えずに済む | 事前学習の知識が効く課題での可能性を、今回は検証しないまま保留する |
| B | Must のまま、ベースモデル持ち込みの非既定候補として基準を緩めて実装する | REQ-41 の当初目標（2026-10-06 判断）を維持 | 下の「初期アーキテクチャ」の作業量が大きい。p95 250 ms と RSS 2 GiB は現状の採点方式では満たせない |

A の再開条件（案）: 次のいずれかが示されたら REQ-41 を再検討する。

- C3 が届かない課題（事前学習の知識が要る等）で、P 系の候補が凍結 test で有意に上回る
- 容量 100 MB 級以下のベースモデルで、品質が C3 以上
- 共通プレフィックスの使い回し（下記）などで、p95 250 ms 未満・RSS 2 GiB 未満を実機で示せる

追加学習を既定候補に入れない扱いは、案によらず変えない（PoC-26 の「失敗時の扱い」）。

### 2. 受け入れ基準の確定案（B を選ぶ場合、または再開時の基準）

| 項目 | 確定案 | 根拠 |
| ---- | ---- | ---- |
| 品質 | 同じ評価器・凍結 test で majority と既定候補の最良に対する McNemar / Holm の結果と Wilson 区間を記録する。有意に上回ることは合格条件にしない | spec の暫定案を維持。①の結果 |
| 正常系 | `env -i`（Python・MLX なし）で推論が成功し、学習側（MLX）との予測ラベルが全件一致する。logits の差は最大絶対差を記録する | REQ-32・REQ-28。③の数値照合 |
| logits 差の許容 | float32 同士で最大絶対差 1e-3 以下（追補 1 の 6.2 と同じ値）。今回の 9.4e-4 はこの範囲に収まる | 追補 1 の 6.2・#392 |
| トークナイザー | HF `tokenizers` の golden と token id が全件一致 | #390・`fixtures/poc26/` |
| 容量 | 内訳を記録し、40 MB 超は警告のみ（拒否しない） | オーナー判断 2026-10-06（#381） |
| RSS | ガード層の 2 GiB 上限を維持する。超える場合は拒否（`limit_exceeded`） | REQ-39・オーナー判断 2026-10-06 |
| p95 | 推論のみの p95 を記録し、250 ms は REQ-41 の候補には警告扱いとするか、拒否条件とするかをオーナーが決める | ②の結果（現状 1084 ms） |
| 読み込み上限 | 1 GB の単位（10^9 か 2^30）を決める。float32 の ONNX（約 1.98 GB）は超えるため、bf16 / fp16 での書き出しが前提になる | #400・`05-tasks.md` の未決事項 |
| 異常系・境界値・来歴 | spec の暫定案を維持 | REQ-41 |

### 3. 初期アーキテクチャの案（B を選ぶ場合）

1. 書き出し: LoRA を統合した単一モデルを bf16 または fp16 で書き出す（float32 では読み込み上限を超える）。ベース重みのライセンス上の同梱可否は未決（#387）で、別途判断が要る
2. 推論ランタイム: C1・C3 のテンプレート照合とは別に、Qwen2 系の decoder を扱う経路を足す。汎用 ONNX 演算 11 種の実装か、ONNX を使わず safetensors を直接読む専用 forward かを選ぶ。どちらも std のみの行列積では CPU の p95 が MLX の CPU（15.7 秒）より遅くなる見込み（推定）で、Metal / Accelerate を使うには FFI（`unsafe`）か依存の追加が要る（いずれもオーナー承認事項）
3. トークナイザー: byte-level BPE を自作するか依存を足すか（`05-tasks.md` の未決事項）
4. 採点: 26 選択肢で共通するプロンプト部分の計算を 1 回にし、選択肢ごとの短い続きだけを計算する（KV の使い回し）。p95 の短縮幅は未測定
5. 資源上限: RSS は現状でも GPU で境界値のため、読み込み時の重み複製を避ける実装が前提

A を選ぶ場合、上記は再開時の出発点として残すだけで実装しない。
