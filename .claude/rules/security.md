# セキュリティ規約

## 秘密情報の混入防止（P0）

- 実トークン・API キー・接続資格情報をコード・テスト・fixture・ドキュメントに書かない（例示はダミー値に限る）
- `.env` 等の資格情報ファイルをコミットしない（`.gitignore` 済み）。資格情報をログ・エラーメッセージ・CLI の JSON 出力へ出力しない
- hooks・settings.json にシークレットをハードコードしない
- 学習・評価データに個人情報・機密情報が含まれうることを前提に、データ本文をログ・エラーメッセージ・Issue・PR へ転記しない

## ガード層（P0。REQ-39・PoC-20）

CLI・MCP・TUI から渡される入力は untrusted として、処理の手前（ガード層）で検査する。PoC-20 で「ガード層の無い CLI には防御がない」ことを実測済み。

- **経路の閉じ込め**: `../`・絶対パス・symlink によるルート外参照を `safe_join` 相当の検証（正規化後にルート配下であることの確認）で拒否する
- **形式の許可制**: 読み込むモデル・データの形式を許可リストで判定する。pickle 偽装・非 ONNX ファイル・非対応の `kind` は拒否する。任意コード実行につながる形式（pickle 等）を読み込まない
- **資源の上限**: 1 件あたりの処理時間・RSS・ファイルサイズ（読み込み前に確認）に上限を設ける（暫定値は spec の REQ-39 を参照）。無制限のアロケーション・無限待ちを作らない
- **完全性と版**: 配布パッケージ・モデルは sha256 で検証し、不一致なら拒否する。読み取り専用配置への書き込みを拒否する。`kind_version` は許可リストで検証し、版管理台帳から前版へ戻せるようにする

## ローカル完結（REQ-38）

- 推論・学習・評価の実行時に本ツール起因の通信を発生させない（テレメトリ・自動更新・重みの自動ダウンロードを持たない）
- 通信を伴う操作（依存・重みの取得）はユーザーの明示承認を経てから実行する

## MCP・エージェント連携（REQ-36・REQ-37）

- MCP サーバーはローカル（stdio 等）に限り、既定でネットワークインターフェースへ公開しない
- 学習・削除など副作用の大きい操作は、推論・一覧・評価参照と分けて公開し、利用側で拒否設定できるようにする
- MCP リクエストの入力も CLI と同じガード層を通す

## OWASP Top 10 観点（PR 作成前チェック）

| 観点 | 本リポでの具体例 |
| ---- | ---------------- |
| インジェクション | CLI 引数・定義ファイル・MCP リクエストを子プロセス起動・パス・シェルへ未検証で連結 |
| アクセス制御の不備 | MCP をネットワークへ公開・読み取り専用配置への書き込み |
| 不安全な設計 | 無制限の資源確保（巨大ファイル・無限長入力・タイムアウト欠如）・ガード層の迂回経路 |
| ソフトウェアとデータの完全性 | モデル・配布パッケージの sha256 未検証・評価データのハッシュ未検証・pickle 等の安全でない逆シリアル化 |
| 脆弱な依存 | 未固定バージョン・メンテ停止パッケージ（[dependency-policy](./dependency-policy.md)） |

## 運用

- `git commit --no-verify` を使用しない（pre-commit フックを必ず通す）
- 攻撃入力の検証は模擬データ・テストハーネスで行い、実環境の重要データに対して実行しない
- セキュリティ上の疑義を発見した場合は作業を中断してユーザーに警告する
